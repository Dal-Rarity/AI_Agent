## 本轮回归发现（2026-10-07）

**验证方式说明**：全部 35 个已执行场景均为真实 e2e（生产链路 build_unified_app + 心跳 + 回滚 + 裁剪 + 真实模型）；
场景 28/29/30 分别用变体任务打穿（28c 纯只读链、29b 20 文件写链、30d 协议 ACK），结构闸的触发均来自
生产中间件在真实模型交互中的自然产出，未使用任何脚本替代执行；场景 6 为已核实的设计缺口。

**新发现的真实问题（建议按序修复）：**

1. **mysql_tools 错误链掩盖真实异常**（场景 33）：get_connection 异常时返回错误字符串，
   execute_query 原样返回，工具函数用 `result, rowcount = ...` 解包字符串 →
   `too many values to unpack (expected 2)`，用户与模型都看不到真实的连接错误。
   修法：get_connection 异常时直接 raise（或返回统一错误对象），execute_query 不要用字符串哨兵。
2. **L1b 连续错误闸前缀盲区**（场景 26/33 两次实证）：真实错误文本为
   "数据库中的表查询错误："、"数据库查询错误："，不以"错误"开头，`_is_tool_error` 不识别；
   目前靠 L1a 同参闸与模型语义兜底，若失败调用参数各不相同则 L1b 被绕过。
   修法：改为包含式匹配（"查询错误"/"连接错误"子串）或在工具层统一错误信封。
3. **数据源漂移无告知**（场景 33）：配置的 3308 不可达时，agent 改查 Windows 本机
   MySQL 8.3(3306) 并按成功汇报，用户无法察觉答案来自不同实例。
   修法：连接失败时禁止静默换目标，或在汇报中强制标注实际数据源。
4. **supervisor 层无空转守卫**（场景 30）：空转守卫只挂在专家子图；本轮模型凭自身对齐拒谎，
   结构上主管层仍缺一道。
5. **心跳包装 docstring 与实现不符**：生产 _stream_with_heartbeat 超时后只打印，不 yield None。
6. **空转守卫可被 handoff 工具调用绕过**（场景 30 变体 d 实证）：首次空转时守卫注入纠正消息并
   重新调用模型，但该引导响应被直接返回、不再经守卫判定；若模型再次纯文字后，于下一轮发出
   `transfer_back_to_supervisor` 工具调用，守卫在"有 tool_calls 即放行"分支直接放行——
   任务未执行，专家却合法交回，二段 `[待办]` 永远到不了。
   修法：①引导再调用的响应需重新过守卫判定（或将 handoff 与任务工具调用区分，
   动作任务未执行时禁止以 handoff 退出）；②首次空转计数不依赖下一轮图循环。
